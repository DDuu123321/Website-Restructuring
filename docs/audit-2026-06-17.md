## 四、新发现（全部经对抗式复核）

### 🔴 P0 — 上线前必须解决（部署阻塞，本地开发无碍）

**P0-1　无数据库迁移流程，生产 schema 同步两条路都出事**
`cms/` 无 `src/migrations/` 目录，`package.json` 无 `migrate` 脚本。`@payloadcms/db-postgres` 的 `connect.js:80` 用 `NODE_ENV !== 'production'` 门控 dev-push：
- 带 `NODE_ENV=production` 部署 → 跳过 push 且无迁移 → 全新库永远建不出表 → Payload 首查崩溃、/admin 打不开。
- 不设 `NODE_ENV=production`（而 `cms/.env` 恰恰硬编码了 `NODE_ENV=development`）→ 每次启动对**生产库**跑 dev-push，按当前代码 ALTER/DROP 列 → schema 漂移/数据损坏。

今天没有安全的首次生产部署路径。修：加 `migrate`/`migrate:create` 脚本 → 本地生成并提交初始迁移 → 部署前跑 `payload migrate` → 设 `NODE_ENV=production`，并可显式 `push:false`。
证据：[package.json](../cms/package.json) scripts、`@payloadcms/db-postgres/.../connect.js:80-83`、[.env](../cms/.env):4。

**P0-2　Media 落本地磁盘，PaaS 每次重新部署即丢全部上传**
[Media.ts](../cms/src/collections/Media.ts) `staticDir` 指向本地 `../../../uploads`，[server.ts:119](../cms/src/server.ts:119) 用 `express.static` 直接吐盘，`payload.config.ts:76` 注释自承"local for now — swap to S3/R2 later"，依赖里无 `@payloadcms/plugin-cloud-storage`。按既定双服务拓扑（CMS 单独上 PaaS），容器盘重启即清空——logo/hero/新闻/项目图首次重新部署后静默消失。修：装 `@payloadcms/plugin-cloud-storage` + S3/R2 适配器。（06-12 已列，仍未做。）

### 🟠 P1 — 真实缺陷，应尽快修

**P1-1　未登录访客可把未审核评价自我置顶到首页（越权）**
Testimonials `create:()=>true`，但 `pinned`（[Testimonials.ts:73](../cms/src/collections/Testimonials.ts:73)）、`sortOrder`、`status` 均无字段级 `access.create`；beforeChange 只 `{ ...data, status }` 覆盖 status，`pinned`/`sortOrder` 从客户端原样穿透。首页 `api.testimonials({pinned:true})` 按 `-pinned,sortOrder` 排序优先渲染。攻击链：`POST /api/testimonials {pinned:true,sortOrder:-9999,review:"…",rating:5}` → 未审核评价霸占首页社会证明位（刷屏/抹黑/竞品攻击）。代码他处已用过 `honeypotField` 的字段级 `access`，说明这是遗漏而非框架默认保护。
修：给 `pinned`/`sortOrder`/`status` 加 `access:{ create/update: ({req}) => !!req.user }`，或在公开分支强制 `pinned:false, sortOrder:100`。

**P1-2　公开 lead 集合存在无上限文本/JSON 字段**
Quotes/Assessments 多数 text 字段无 `maxLength`：Quotes `firstName`(必填)/`lastName`/`address`/`suburb`/`roofType` 及整个 `source` 组；Assessments `answers.*`/`result.*`，尤其 **`result.scores` 是 `type:'json'` 且无任何 `validate`**——未登录 POST 可塞任意大/深 JSON。16kb body 上限只挂在 `/api/chat`，lead 端点走 Payload 默认 ~2MB 解析器。10 POST/min 下可持续写几百 KB 的行，撑大 Postgres + admin 列表/CSV 导出，且超大值会被插进通知邮件。
修：给所有公开可写 text/textarea 补 `maxLength`；`result.scores` 改服务端写入或加大小/深度 `validate`。

**P1-3　启动无环境变量校验，localhost 兜底掩盖生产误配**
[server.ts:131](../cms/src/server.ts:131) `process.env.PAYLOAD_SECRET as string` 无守卫（未设则 JWT 可伪造/启动晦涩失败）；`payload.config.ts:70` 把 `DATABASE_URL` 兜底成硬编码 localhost；`SERVER_URL` 兜底 `http://localhost:3001`。生产缺 `DATABASE_URL` 会静默连本地默认库而非"大声崩"。SMTP/GEMINI 只在调用时软检查（客户提交静默不发邮件）。修：启动前 fail-fast 断言关键 env；去掉硬编码 localhost DB 兜底。

**P1-4　/reviews 缺 AggregateRating + Review 结构化数据**
[_ReviewsView.tsx:21](../frontend/src/app/reviews/_ReviewsView.tsx:21) 已算出 `avg`/`counts`/`reviews.length`，却不输出任何 JSON-LD，富摘要数据现成却丢弃；`seo.ts` 无 `aggregateRatingLd`/`reviewLd`。修：加 helper，在 /reviews 输出，并把 `aggregateRating` 挂到 LocalBusiness `@id`（Google 要求被评主体是企业）。

**P1-5　`.text-eyebrow` 黄字压浅底，全站对比度不达标（WCAG AA）**
[design-system.css:187](../frontend/src/styles/design-system.css:187) `color: var(--bv-teal-600)` = #e8b300（实为黄色）12px/700，压白底实测 **1.93:1**、压 paper **1.78:1**（AA 正文需 4.5:1）。在 Products/About/FAQ/Rebates/Home/PageHeader 浅色变体反复出现。修：浅底用深墨色或加深金（#8a6d00=4.92:1），亮黄只留给深底。

> 复核降级说明：以下两项被独立复核从 P1 降为 **P2**——
> - **Product/Offer JSON-LD 缺失**：/products 有"From $5,990/$13,490/$22,990"但无 Product 结构化数据。降级因这是"From …含补贴"的引流估价、非可结账 SKU，富摘要资格与收益都边际，且属增强而非 bug。
> - **FAQPage JSON-LD 与可见内容不符**：CMS 无 FAQ 时 `faqLd([])` 输出空 `mainEntity`，但页面渲染 24 条 `FALLBACK_FAQS`。降级因方向是"少报"（不会触发处罚，只是丢富摘要），修法是 page 与 view 共享同一份 fallback。

### 🟡 P2 — 锦上添花 / 条件性（精选，完整清单见附录）

## 五、/rebates 内容事实核查（2026-06 澳洲补贴现状）

**总评：这页内容质量很高，把行业最常搞错的几个点都答对了。** 由于既定业务规则"页面零金额"，它天然免疫绝大多数金额类陈旧风险。

✅ **核对准确的关键陈述：**
- 联邦 Cheaper Home Batteries 自 **2025-07-01** 起生效；**2026-05-01 退坡**、此后每 1/1 与 7/1 继续递减直至 **2030 年底**关停。
- **VPP-capable（具备能力）即可，无需真正入网** —— 这是全行业最常被搞错的点，页面答对了。
- 电池须在 CEC 批准清单、配套光伏、持证安装商、**一址一台、无收入审查**。
- 联邦光伏 STC 每 1/1 递减、**2030 年底前完全退出**。
- NSW VPP 接入激励**可与联邦叠加**；**QLD Battery Booster 已关停**、转走联邦。

⚠️ **建议补全/复核（不是错误，是缺口）：**
1. **未提"按容量分档退坡"**：自 2026-05-01，STC 系数按可用容量分档（前 14kWh 计 100%，14–28kWh 计 60%，28–50kWh 计 15%）。页面写"Bigger batteries earn more, up to the program's cap"略有误导——超过 14kWh 的部分其实**每 kWh 补贴更少**。建议加一句分档说明。
