# Bluven CRM / ERP 概念地图（讨论稿）

> 日期：2026-06-17 ｜ 状态：**纯讨论，未开工** ｜ 对象：单人开发、CRM 领域小白
> 目标：在写第一行代码前，把"一个澳洲家用光伏+储能零售商的全流程系统该长什么样"这件事彻底想清楚。
> 已定方向：**自建** · **独立系统**（不寄生现有 Payload 网站后台）· **单向接收**网站线索（网站→CRM，CRM 不写回网站）· **全生命周期** · 财务接 **Xero**。

## 0. 一句话总览（先看这个）

> **真正的顶尖同行也不"全自建"。他们的赢法是：自己拥有「客户+工单+流程」这套数据中枢，然后把"太难自建"的环节（系统设计/出图、设备监控、会计/工资）用 API 接进来。你该做的也是这件事——建中枢，接商品化的边角。**

把"自建一个全生命周期 CRM/ERP"翻译成可执行的版本就是：
- **建**：客户/线索/商机/工单/活动日志/合规档案/作业成本 这套**业务中枢**。这是你的护城河，别人没有为你定制。
- **接**：系统设计与出图（OpenSolar/Aurora）、设备监控（Enphase/SolarEdge/Sungrow 各家云）、会计与工资（Xero）。这些是别人做到极致的商品，自建是浪费生命。
- **跳过**：制造/BOM 生产、仓库库位管理、多币种多主体、自研工资单。单人开发这些是项目埋葬场。

## 1. 先建立概念：CRM 到底是什么，和 ERP 什么关系

你是小白，先把这两个词钉死，后面才不晕。

| | **CRM** | **ERP** |
|---|---|---|
| 行话 | **前台**（front office） | **后台**（back office） |
| 朝哪看 | 向**外**看客户 | 向**内**看运营 |
| 核心问题 | "怎么赢得并留住客户？" | "怎么交付并把账算清？" |
| 主数据 | 人、商机、对话 | 钱、库存、订单、资源、工单 |
| 管什么 | 市场 / 销售 / 客服 | 财务 / 采购 / 库存 / 项目 / 人事 |

**两者的接缝在哪？** 在 **「报价 → 成交订单」** 这一刀。CRM 把你带到"客户接受报价"为止；一旦它变成一个要备料、要下采购单、要开发票、要排安装的**承诺工单**，你就进了 ERP 的地盘。**这一刀正好是你太阳能生意的命脉**：
`线索 → 勘测 → 报价 → 成交 → 采购板/逆变器/电池 → 排安装 → 开票 → 质保`。

**为什么大家都先做 CRM 再长成 ERP？**
1. **CRM 直接挣钱**（帮你成单），ERP 是优化成本，得先有量才谈得上优化。
2. **CRM 范围窄**（就 3 块：市场/销售/客服），几周能跑起来；ERP 几乎碰每个部门，是几年的工程。
3. **痛来得晚**：库存乱、现金流看不清、排期撞车，都是"上规模后"的痛。

**一个要背下来的不对称**：*大多数 ERP 自带 CRM 模块，但 CRM 不含 ERP 功能*（没有总账、没有真库存、没有交易级会计）。所以"长成 ERP"通常意味着你的 CRM 中枢被一个更大的运营平台吸收/集成。**对你来说，这意味着——一开始就别把它设计成"纯 CRM"，要设计成"以客户和工单为中心、能往 ERP 长"的中枢。**

## 2. 顶尖同行怎么做的（Benchmark）

### 2.1 市场分成四层，没有一个产品四层都强

```
设计/出图   →   CRM/销售   →   现场作业/运营   →   监控/客户体验
(Design)        (Sales)        (Field Ops)         (Monitoring/CX)
```

| 层 | 代表产品 | 干什么 |
|---|---|---|
| **设计/出图** | **OpenSolar**(澳洲)、**Aurora**(美·设计金标准)、**Pylon**(澳·按项目收费)、Solo | 地址+电费单 → 3D 屋顶建模、阴影分析、发电量估算、电池选型、漂亮的可签约提案 |
| **CRM/销售** | Salesforce、HubSpot、Zoho、SolarNexus、Sunbase | 线索分配、管线阶段、双向短信/邮件、跟进自动化、电子签 |
| **现场作业/运营** | **simPRO**(布里斯班·澳洲最强)、**AroFlo**(澳/新)、Fergus(澳/新·小团队)、Scoop、ServiceTitan(美·重) | 排班派工、装机师傅手机端、工单清单、拍照、库存、合规文档、开票 |
| **监控/客户体验** | **Bodhi**(售后体验标杆)、Enphase/SolarEdge/Tigo 各自的云 | 装机后发电监控、多品牌机群聚合、故障告警、业主门户、主动沟通防流失 |

### 2.2 想做"全家桶"的，赢法有两种相反路线

- **自建型 monolith**：OpenSolar、Sunbase——四层模块自己全做。
- **编排型 orchestrator**：**Enerflo**——它自己**不做**设计，而是开放 API 把最强的拼起来（Aurora 做设计、Salesforce 做 CRM、贷款方做金融），自己只拥有"统一数据层 + 流程引擎"，号称把装机周期砍了 ~62%。

> **这条给你的启示最重要**：对一个自定义系统，**编排型几乎总是更明智的架构**——你拥有数据模型和流程引擎，把最难的专业件（设计、监控）接进来。这正好印证了第 0 节的结论。

### 2.3 顶尖产品做对、而"naive 自建"会漏掉的 7 件事

1. **录一次、全程流动**（single source of truth）。线索/勘测填的数据，原封不动流到提案→合同→装机工单→监控。Scoop 的 "Global Fields"、OpenSolar 的"单一项目流"都为这个存在。naive 做法是做 4 个互不相干的表单，反复重录——这是头号成本。
2. **第一天就有开放 API + webhook**。设计和监控太难自建，要规划成"接"，不是"造"。
3. **售后/客户体验模块，没人记得排**。Bodhi 之所以存在，是因为装机商把 PTO（并网）当"结束"，然后被售后工单、差评、流失打死。一个带品牌的业主门户 + 多品牌监控聚合 + 主动沟通，是竞争武器——而且**直接喂养你网站的 reviews 和转介绍**。
4. **多品牌监控聚合**。Enphase/SolarEdge 各家的监控免费但互相隔离；真实机群是混装的，不聚合就没法统一服务。
5. **提案卖的是"全屋电气化+省钱故事"，不是瓦数表**。OpenSolar 3.0 / Aurora 现在每个提案都带电池、带 EV/热泵/燃气对比的生活方式叙事。
6. **金融/信贷申请嵌在流程里**。报价那一刻就能申请分期/绿色贷款（澳洲如 Brighte、Plenti、Humm），把"金融变成单独一步"会让成交卡死。
7. **硬件下单接到设计上**。设计出来的 BOM 直接变成可购买的购物车（OpenSolar→Solar Outlet）。

### 2.4 美国工具会漏掉的"澳洲特有"环节（你必须自建/本地化的部分）

美国参照系（Aurora/Solo/Bodhi/ServiceTitan/Enerflo）**不编码澳洲流程**。下面这些是你系统里别人替代不了、必须自己长出来的核心：
- **STC 退补引擎 + 审计档案**（按邮编分区算证书、装机自拍 geotag+时间戳、合规证书清单）。
- **SAA 认证**（2024 起取代 CEC 认证）——装机师/设计师资质要逐单校验。
- **CEC 认证产品清单**——板/逆变器/电池必须在批准清单内才有退补资格，要嵌进选型/BOM。
- **DNSP 并网预批**——装机前的硬前置（连接申请、出口限制、电池报备）。
- **澳洲会计**——接 Xero/MYOB（这正是 simPRO/AroFlo/Fergus 在澳洲吃得开的原因）。

## 3. 你的业务全生命周期（12 阶段 + 每阶段产生的数据）

这是整个系统的骨架。**每个阶段产生的数据，就是你数据模型的字段来源。**

| # | 阶段 | 发生什么 | 产生的关键数据/文档 |
|---|---|---|---|
| 1 | **线索捕获与初筛** | 网站表单/电话/转介绍进来；筛产权、屋顶、电费、是否已有光伏、邮编 | 联系人；邮编→**STC 分区(1–4)**+州补贴资格；用能档案（季度电费/kWh/电价/零售商）；线索来源/状态/负责人 |
| 2 | **现场勘测** | 卫星图(Nearmap)+常含实地：屋顶材质/朝向/坡度/遮挡、**配电箱**状况、电表、电池安装位 | 屋顶模型；遮挡分析/年发电量；**配电箱照片+是否需升级**；电表照片+NMI；电池布线 |
| 3 | **系统设计与选型** | **CEC/SAA 认证设计师**选板/逆变器/电池；守 DNSP 出口限制和 AS/NZS 4777.2；**必须用 CEC 批准清单内产品** | BOM（型号×数量）；单线图/串列；发电+自用建模；回本估算；**产品清单合规校验（型号+到期日）** |
| 4 | **提案/报价** | 客户面提案：系统、发电、省钱、**已扣 STC 折扣和各项补贴后的净价** | 报价行项目（毛价/STC 折扣/联邦电池补贴/州补贴/净价）；省钱模型；STC 数量与假设单价 |
| 5 | **合同/定金/金融** | 签约（Approved Retailer 须守 CEC 行为准则：冷静期/质保/明价）；收定金（常 10–20%）；分期/绿色贷款 | 签约合同；付款计划（定金→进度→尾款）；定金发票；金融申请；**STC 授权书** |
| 6 | **STC 创建/转让/交易（退补引擎核心）** | 客户把创建 STC 的权利**转让给注册代理**（你或专门 STC 交易商），代理创建并卖出证书，**把价值作为售点折扣前置返还** | `STC = 系统kW × 邮编分区 × deeming年数(向下取整)`；2025 deeming=6 年(每年1月减1，2030 结束)；STC 价 ≈ $39–40（清算上限 $40）；REC Registry 记录；须在装机后 **12 个月内**创建 |
| 7 | **联邦+州补贴**（2025–26·**易变**） | 见下方专栏；**作为售点折扣由零售商先垫、再靠卖证书回收** | 各补贴的资格判定 + 金额（按邮编/州/电池属性） |
| 8 | **CEC/SAA 认证与批准产品**（贯穿） | 装机师/设计师 **SAA 认证**+装机州**无限制电工执照**=创建 STC 的强制条件；产品须在 CEC 清单且未过期 | 装机师 SAA ID+到期+执照；设计师认证；产品型号 vs 当期 CEC 清单 |
| 9 | **DNSP 并网审批** | 装机前向配电网申请连接+出口限制（VIC 须先拿到才能进 Solar Victoria 门户）；CSIP-AUS 柔性出口渐成强制；装机后报完工+电表改双向 | DNSP 申请号；批准出口限制；连接批准；NMI；电表改配确认 |
| 10 | **安装/调试/电气安全证书** | 认证装机师+持证电工装机调试；**州别安全证书**：NSW=**CCEW**(7天内)，VIC=**COES**(须独立检查员,28天内)，QLD/SA 各自 | 装机日期；**调试/签核日期(锁定退补档位)**；证书号；检查员(VIC)；**板/逆变器/电池序列号**；geotag 装机照(审计证据) |
| 11 | **交付/质保/监控** | 交付包(手册/单线图/证书/质保/监控 App)；**三类质保**：①厂商产品 ②安装工艺(Approved Retailer 最少 5 年) ③性能(25 年≥80–87%)；设置监控+VPP 入网 | 质保登记表(部件/年限/起始/序列)；监控账户；VPP 入网记录 |
| 12 | **售后/维护/质保索赔** | 故障处理、监控告警、定期维护、**质保索赔(向厂商 RMA)**；CER 可能审计 | 服务工单；RMA/索赔记录；上门排程；用料(回链库存+作业成本) |

### 专栏：补贴（2025–2026 现状，**会半年一变，别硬编码**）

- **联邦 — Cheaper Home Batteries（2025/7/1 起）**：通过 SRES 给电池发**额外 STC**，**售点折扣**。条件：电池 **5–50 kWh 可用**、在 CEC 批准电池清单、CEC 认证装机师、**VPP-capable**（联网可远程调度，实际入网可选）、须配新/旧光伏、**每户一次**、**不查收入**。早 2026 约 **$330/kWh**，逐步降；**2026/5/1 起分档**：0–14kWh=100%、14–28kWh=60%、28–50kWh=15%，此后每 6 个月降一次。
- **NSW**：售点电池补贴(BESS1) **2025/7/1 结束**；现为 **VPP 接入激励**（接入注册 VPP 一次性最高 **$1,500**，靠 PRC 证书返还），可叠加联邦。
- **VIC（Solar Victoria）**：电池无息贷款 2025/5 结束；**无在用州电池补贴**；光伏补贴+无息贷款(约$1,400)仍在(2026/7 起收入限制)。电池只走联邦。
- **SA/QLD**：州电池方案已结束，主要走联邦。

> **设计含义**：把补贴建成**可叠加的激励**（联邦 SRES STC 折扣 + 可选州 VPP/PRC/REPS），每个有自己的、**按日期生效的版本化规则表**，键于邮编/州/电池属性。**调试日期是承重字段**，决定档位与 deeming 年。

## 4. 一个太阳能零售商的 CRM 该有哪些模块（清单）

勾选你真正需要的（标 **现在需要 / 以后 / 永不**）：

- [ ] **联系人/客户管理** — 每个人和组织的唯一真相源（业主/strata/builder）
- [ ] **线索管理** — 捕获、初筛、分配、打分
- [ ] **商机/管线管理** — 命名阶段推进（询价→勘测→已报价→赢/输）
- [ ] **活动/互动记录** — 每通电话/邮件/上门/备注挂到联系人（"上次跟他说到哪了"）
- [ ] **报价/CPQ** — 从产品目录按规则生成报价 ← **这是 CRM↔ERP 的桥**
- [ ] **产品/价目表** — 卖什么、什么价
- [ ] **市场/活动** — 邮件/短信触达并归因回线索
- [ ] **客服/工单(case)** — 售后问题/质保索赔追踪到关闭
- [ ] **评价/反馈/NPS** — 你网站已经在做，这本就是 CRM 功能
- [ ] **报表/仪表盘** — 管线价值、转化率、赢输、来源 ROI
- [ ] **邮件/日历集成** — 免双重录入
- [ ] **自助门户** — 客户自查状态/报价/工单

## 5. 做成 ERP 是什么样（哪些要、哪些坚决跳过）

ERP 模块全集很大，你**只会用到一小撮**。原则：**自己独有的就建，已被解决的商品就买**（会计/工资在澳洲既是商品又有法律雷，**买**）。

| ERP 模块 | 对你 | 说明 |
|---|---|---|
| **财务/会计**（总账/应收应付/GST/对账） | **买(Xero)** | ERP 的不可谈判内核，但你买不自建 |
| **订单管理** | 建 | 把成交报价变成可追踪的工单 |
| **采购/PO** | 建(轻) | 给具体工单向批发商下单(板/逆变器/电池) |
| **库存** | 建(轻) | 先做"数量"，别做库位 |
| **仓库管理(库位/拣货)** | **永不** | 太阳能零售用不上 |
| **项目/工单管理** | **建(运营心脏)** | 每个装机=一个工单：任务/里程碑/成本/利润 |
| **现场服务(排班派工/手机端)** | **建(关键)** | 太阳能直接相关，师傅在屋顶不在桌前 |
| **制造/BOM 生产** | **永不** | 你装机不制造 |
| **专业服务(工时/计费)** | 看情况 | 若按工时计费才需要 |
| **HR/工资** | **买** | 澳洲工资单(super/award)极复杂，永不自建 |
| **资产管理(车/工具)** | 以后 | |
| **BI/分析** | 以后 | 跨销售+工单+财务看利润 |

> **你的甜区**：**CRM 核心（第 4 节）+ 两个 ERP 模块（工单管理 + 现场服务）+ 坚实的平台地基（第 7 节），会计和工资买不建。** 这一句话基本定义了"可被一个人做完"的全生命周期系统。

## 6. 财务：Xero 接入边界（什么该接、边界划在哪）

### 同步什么

| 领域 | 你的系统侧 | Xero 侧 |
|---|---|---|
| 客户 | 线索→赢单 | **Contact**（名/ABN/邮箱/账期）双向 |
| 报价 | 提案/报价 | 留在你系统，赢单时转 Invoice |
| 定金/进度/尾款 | 工单上的付款计划 | **Invoices** + **Payments** |
| 物料 | BOM(板/逆变器/电池) | **Items** |
| 供应商采购 | PO | **Purchase Orders → Bills**(应付) |
| 人工 | 装机/电工工时、分包发票 | **Payroll**(员工)、**Bills**(分包) |
| 工单盈亏 | 按项目作业成本 | **Tracking Categories**(每张发票/账单带"项目"维度) |
| 税 | 无 | **GST** 自动算、**BAS** 在 Xero 报 |

### 接入方式与限制（建系统要知道）
- **直连 Xero API（OAuth2）**：access token **30 分钟**过期(refresh 60 天、每次轮换)；**Webhook 只有 Contacts 和 Invoices** 两种资源(验 `x-xero-signature` HMAC-SHA256，过"intent to receive")，其余靠 `If-Modified-Since` 轮询；**限流 60/分、5000/天/组织、5 并发**，超了 429+指数退避。
- 关键字段：**Contact** 是你系统和 Xero 的连接键；**Invoice** 的 LineItems 带 AccountCode/TaxType/**TrackingCategory**；**Tracking Category 每组织最多 2 个**——把**其中一个=你的工单/项目 ID**，Xero 就能按工单出 P&L，你不用重造会计。

### 边界铁律
- **你的系统拥有"运营真相"**：卖了什么、怎么设计、怎么装、交付花了多少、欠供应商多少（运营层）。还有**全部太阳能合规数据**（STC/补贴资格/CEC 校验/SAA/DNSP/证书/序列号/质保/监控）——这些**绝不进会计**。
- **Xero 拥有"财务真相"**：总账、应收应付、对账、GST/BAS、工资/STP、**发票/账单的法定记录**。
- **同步 Contacts + Invoices/Payments**（可选 Bills/PO + Tracking）。**每个字段只设一个 master**（你的系统 master 工单数据，Xero master 收款状态），避免双向打架。
- **补贴是零售商先垫的售点折扣，再靠卖 STC/PRC 回收**——这是**两个独立的账务事件**：客户看到的"折扣" vs 企业收到的"卖证书现金流"。建模时分开。

## 7. 跨领域地基（每个系统都要、小白最常忘，要先建进地基）

- [ ] **身份认证** — 登录/改密/2FA/SSO。这错了别的都不安全
- [ ] **角色权限(RBAC)** — 装机师不该看利润；事后补权限是噩梦，**一开始就设计**
- [ ] **审计日志/活动历史** — 谁、何时、改了什么（"报价被谁改了价？"）。**append-only**
- [ ] **文档/文件管理** — 报价/合同/合规证书/现场照/数据表。太阳能每单产生海量文档
- [ ] **通知** — 邮件/短信/站内（新线索/已排期/待付款）。你网站的通知开关思路是对的
- [ ] **报表/仪表盘** — 每个模块都产数据，得有人不导出 Excel 就能看
- [ ] **搜索** — 500 联系人 2000 文档后，"找"是最高频功能
- [ ] **移动/现场端** — 师傅在屋顶；哪怕只读的"今日工单"也高价值
- [ ] **集成与公开 API** — 会计(Xero)、支付、邮件/短信、CER/STC。干净的内部 API 是这一切的前提
- [ ] **数据导入/导出** — 从 Excel 迁入、CSV 给会计。你已有批量 CSV，沿用
- [ ] **隐私与留存** — 澳洲 Privacy Act/APP 管客户 PII：存什么/为什么/存多久/怎么删
- [ ] **备份与灾备** — 最无聊但救命的。自动+异地+**演练过恢复**（没恢复过="没有备份"）
- [ ] **多币种/多主体** — **跳过**（单 AUD 单 ABN），但要**有意识地决定不做**
- [ ] **可配置 vs 硬编码** — 管线阶段、价格、**STC 值**、邮件模板、税率**都会变**；非开发者要改的东西放数据/配置，别写死。这是"你能不能改一下…"痛苦的头号来源

## 8. 数据模型草图（全生命周期的实体关系）

以**人/客户**和**站点**为中心，工单贯穿，活动日志和文档横切。

```
Contact（人，按 email/phone 去重）
  ├─ Account（户/商业主体，可选）
  └─ Site / Property（安装地点：地址/NMI/屋顶/配电箱/DNSP 区）   ← 和联系人分开！一人可多处房产
        └─ Deal / Opportunity（一次销售机会：管线阶段/负责人/金额）
              ├─ Proposal / Quote（提案版本：BOM 行项目 + 毛价/补贴/净价）
              ├─ Contract（签约/付款计划/冷静期）
              └─ Job / Installation（工单：排期/班组/勘测/装机/调试日期）
                    ├─ SystemConfig（装了哪些设备 + 序列号）         ← 质保/STC 靠它
                    ├─ ComplianceDossier（SAA 认证/CEC 校验/DNSP 批准/CCEW·COES/geotag 照）
                    ├─ RebateClaim（STC 数量+授权+卖价 / 联邦电池 / 州 VPP）
                    ├─ PurchaseOrder → SupplierBill（采购，回链 Xero Bills）
                    ├─ Invoice ⇄ Xero（定金/进度/尾款，Tracking=Job ID）
                    └─ Warranty（按部件：年限/起始/序列）
  ├─ Activity（贯穿全程：电话/邮件/上门/状态变更 —— append-only 不可改）
  ├─ Document（合同/证书/现场照/数据表）
  └─ ServiceTicket（售后/故障/RMA → 回链 SystemConfig 和库存）

横切：Product/PriceBook（CEC 批准清单内的 SKU）· Inventory（轻量库存）·
      User/Role（销售/设计/装机/管理）· RebateRule（按日期生效的版本化规则表）
```

几个不能含糊的点：
- **Site 独立于 Contact**：卖的是"给某屋顶装系统"，一人可多房产、一房产可换业主。地址内嵌进客户，未来质保/复购就乱。
- **序列号是质保和 STC 的命根子**，装机当场录。
- **Activity 必须 append-only**——这是 CRM 和"带状态的表单库"的本质区别，也是你现在 Payload 后台**没有**的。
- **RebateRule 做成数据，不写进代码**——半年一变。

## 9. 系统边界全景图（谁拥有什么、数据怎么流）

```
 ┌──────────────┐   新线索(单向)   ┌─────────────────────────────┐
 │  营销网站      │  ───────────▶  │      CRM / ERP 中枢(自建)      │
 │ (Payload/Next)│   afterChange   │  客户·商机·工单·合规·作业成本    │
 │  线索原始真相源 │   或定时拉取     │   ← 你的护城河，自己建          │
 └──────────────┘                 └───────┬──────────┬──────────┘
   网站库=入站缓冲                          │          │
   (CRM 宕机也不丢单)            接(API)    │          │  接(API)
                              ┌───────────▼──┐    ┌──▼───────────────┐
                              │  设计/出图     │    │   Xero(会计真相源)  │
                              │ OpenSolar/    │    │  Contacts·Invoices │
                              │ Aurora/Pylon  │    │  Payments·GST/BAS  │
                              └───────────────┘    └────────────────────┘
                              ┌───────────────┐    ┌────────────────────┐
                              │ 设备监控        │    │  支付/短信/邮件      │
                              │ Enphase/      │    │  Stripe·Twilio 等   │
                              │ SolarEdge 各家 │    └────────────────────┘
                              └───────────────┘
```

- **网站**：线索原始真相源；它的 Postgres 已经在持久化每条线索，**天然是入站缓冲**——CRM 没上线/宕机，线索一条不丢，CRM 起来补拉即可。单向流(网站→CRM)比双向同步简单一个数量级。
- **CRM/ERP 中枢**：你自己建的部分，拥有运营真相。
- **Xero**：财务真相源，你接不建。
- **设计/监控**：接商品化的专业件，别自建。

## 10. 我的建议：买什么 / 建什么 / 跳过什么 + 分期路线

### 三句话定调
- **建**：客户/线索/商机/工单/活动日志/合规档案/作业成本（你的中枢）。
- **接**：OpenSolar 或 Aurora（设计出图）、各家监控云、Xero（会计/工资）、支付/短信。
- **跳过**：制造/BOM、仓库库位、多币种多主体、自研工资单。

### 一个你必须认真对待的现实选择
即便顶尖同行也**不自建设计引擎和监控**。OpenSolar 在澳洲**免费**、本地化、能做设计+提案+CRM+下单。所以"自建"对你最理性的含义是：
> **用 OpenSolar（免费）扛设计/提案/出图这一段，你只建别人没为你定制的"中枢+合规+Xero 作业成本+售后体验"。**

这不是劝你放弃自建，而是把"自建全生命周期"收敛成一个**单人能在合理时间点亮**的版本。要不要这么切，是下一步要拍的板。

### 分期路线（架构一次设计到位，交付分四刀；每刀端到端能用了再下一刀）

| 阶段 | 交付 | 内容 |
|---|---|---|
| **Phase 1 销售跟单** | 最小可用 | 接网站线索 → 去重成 Contact → 商机管线 + 活动日志 + 负责人分配 + 报价。**地基**(auth/RBAC/审计/备份)同期建好 |
| **Phase 2 报价/勘测** | | 报价行项目 + CPQ、Site 实体、勘测、文档管理、合同/定金 |
| **Phase 3 安装交付** | 第一个 ERP 模块 | 工单/项目管理、现场服务排班派工、手机端、SystemConfig+序列号、采购+轻库存 |
| **Phase 4 合规·财务·售后** | | STC/补贴引擎(版本化规则)、DNSP/证书合规档案、**Xero 对接**、质保、监控聚合、业主门户/售后 |

> 注意：你想要的"全生命周期"主要落在 Phase 3–4，那也是工程量最大、最像 ERP 的部分。Phase 1 先把"销售跟单"端到端跑通，是验证整套架构、也是最快见价值的一刀。

## 11. 风险与现实（对单人开发的诚实评估）

1. **范围即风险**。独立系统(自管认证/部署/运维/同步) × 全生命周期(含安装/STC/质保=半个 ERP) × 单人——这是所有岔路里最重的象限。**靠"分期交付 + 接商品件"两把刀来压**，否则会困在一个几个月点不亮的大坑。
2. **第二套认证体系**。独立系统=销售/装机团队要单独登录、单独管账号权限，是从零的一块。你已收集 `state`，按州分配是现成抓手。
3. **运维+备份是公司命脉**。这库装的是最值钱的客户数据，备份要演练过恢复。
4. **补贴是受监管且半年一变**——版本化规则表，别硬编码，每次驱动真实定价前回 CER 核对。
5. **设计/监控别自建**——自建这些是把一个人的项目变成不可能。
6. **会计/工资买不建**——澳洲合规雷区。
