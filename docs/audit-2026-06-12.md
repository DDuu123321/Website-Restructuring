# Bluven Energy 网站审计报告（2026-06-12）

> 方法：对标 6 个厂商旗舰站（Sigenergy / Tesla / Enphase / SolarEdge / Sungrow / BYD）+ 4 个同业经销商站（Solar Naturally / 1KOMMA5° / PSC Energy 原 Penrith Solar / Smart Energy），并对线上站（website-restructuring.vercel.app）做 Lighthouse 实测、对 frontend/ 与 cms/ 做全量代码审计。关键安全论断已逐条在源码中复核。

---

## 一、执行摘要

**网站基本盘是健康的**：SEO 基础设施（metadata / sitemap / robots / JSON-LD / OG）齐全，Server/Client 组件划分干净，ISR 策略合理，CMS 访问控制大方向正确，桌面端 Lighthouse 85/94/100/100。这在自建站里已经超过大多数同行。

**三个最大的问题，按影响排序：**

1. **内容差距 > 代码差距**。对标 4 个澳洲经销商站后结论一致：Bluven 缺的不是页面工程，而是 **rebate（政府补贴）内容体系、硬信任数字、认证徽章**。2026 年联邦 Cheaper Home Batteries 计划（~30% off，5 月起阶梯退坡）是全行业的转化钩子，4 个竞品全部把它放在首屏，Bluven 全站零提及。
2. **移动端性能不及格**。首页移动端 63 分、LCP 8.3 秒，根因明确：~8.6MB 未优化 PNG 裸 `<img>` 直出 + 渲染阻塞的 Google Fonts（含零引用的 Cormorant Garamond 5 个字重）。
3. **两个真实安全漏洞**：quote 邮件模板把用户输入的 `notes` 未转义直接插入 HTML（邮件 HTML 注入）；`Users` 集合公开可读（任何人可拉取管理员邮箱列表）。修复都只要几行。

## 二、Lighthouse 实测（2026-06-11，线上站）

| 页面 | Perf | A11y | BP | SEO | LCP | CLS |
|---|---|---|---|---|---|---|
| 首页 · 桌面 | 85 | 94 | 100 | 100 | 1.3s | 0.007 |
| 首页 · 移动 | **63** | 90 | 100 | 92 | **8.3s** | 0.053 |
| /products · 移动 | 85 | 89 | 100 | 100 | 3.5s | 0 |
| /quote · 移动 | 72 | **82** | 100 | 100 | 3.3s | **0.401** |

实测根因（已在代码中定位）：
- `hero-house.png`（转 WebP 省 2.3MB）、`Battery Value.png` / `Why Bluven.png` / `Rebates.png`（各省 0.8~2.3MB）均为 `public/` 裸 `<img>`（[HomeView.tsx:404](frontend/src/app/_components/HomeView.tsx:404) 等），未走 `next/image`
- [layout.tsx:66](frontend/src/app/layout.tsx:66) 渲染阻塞加载 3 个字体族；**Cormorant Garamond 全站零引用**（`--font-serif` 实际映射 Montserrat），JetBrains Mono 有用但可减字重
- /quote 的 CLS 0.401 来自 footer 后渲染偏移；该页表单控件缺 `id`/`htmlFor` 显式关联，range slider 无可访问值输出
- /products 仍在用 Unsplash 占位图（也是内容真实性问题，对应待办"真实素材"）
- 另：首页静态缓存曾陈旧 13 天（`Age: 1121346`），需复核 ISR revalidate 在 Vercel 上是否真正生效

## 三、对标结论

### 澳洲经销商站的"标配"（4 站全有或多数有，Bluven 现状对照）

| 标配项 | Bluven 现状 |
|---|---|
| Rebate 信息首屏露出 + "我们代办全部 paperwork" 承诺 | ❌ 全站无 rebate 内容 |
| 首页硬数字 stat 卡（运营年数 / 装机量 / 客户数 / 评分） | ❌ 无 |
| 认证徽章墙（SAA、New Energy Tech Approved Seller、厂商认证） | ❌ 无 |
| Google 评分聚合徽章（"4.8★ / N reviews"贴在 CTA 旁） | ⚠️ 有自建 reviews 系统但无聚合徽章 |
| 带数字的施工保修承诺（workmanship warranty） | ❌ 无 |
| header 持续报价 CTA + 可点击电话 | ⚠️ 部分（需复核电话露出） |
| "提交询价后会发生什么"4 步流程图 | ❌ 无（与工程师回电模式天然契合，最便宜的可信度提升） |
| 真实安装照片（非 stock 图） | ❌ /products 仍是 Unsplash |
| 服务区域 / 州级 SEO 落地页 | ❌ 无 |
| 询价表单带资格字段（账单区间 / 兴趣产品 / 来源渠道） | ✅ 大部分已有（电费 slider、邮编→州联动）；缺"来源渠道"归因字段 |

### 头部玩家的差异化打法（选做）
- **不设门槛的 rebate 计算器**（PSC Energy：联邦 STC + 电池补贴计算，算完才给 CTA）——观察到的最强单页转化工具，且与 Bluven"不展示报价"的既定策略不冲突（算的是政府的钱，不是 Bluven 的价）
- **Rebate 变动追踪内容**（PSC 每次政策变动数日内出文；1KOMMA5° 开 webinar）——补贴每半年退坡一次，这是常青流量机器，现有 news 集合可直接转向此用途
- 1KOMMA5° 的 30 年施工保修、客户故事视频、实体 showroom 页

### 厂商站值得借（且只借这些）
- Tesla 的**两字段起步**（地址 + 电费 → 再进完整表单），Bluven 已有邮编→州联动可复用
- Enphase 的 **AU rebate 徽章**直接印在产品图上（经销商版更强："we handle the paperwork"）
- Sungrow 的**动画 stat 条** + 首页具名旗舰案例（"13.3kW + 2× 电池，Penrith NSW"挂到 projects）
- BYD 的**保修做标题**（厂商保修 + 自家施工保修叠加成一个承诺区块）
- 明确**不抄**：受众分流巨型导航、经销商定位地图、Tesla 在线下单、多语言架构、厂商级统计口号、SEO 文章农场

## 四、代码与架构发现

### 🔴 P0 — 安全（已逐条源码复核属实）

| # | 位置 | 问题 | 修复 |
|---|---|---|---|
| S1 | [sendQuoteEmails.ts:52](cms/src/hooks/sendQuoteEmails.ts:52) | 用户输入 `doc.notes` 未转义直插 HTML 邮件（sendReviewEmail 转义了，此处漏了；sendAssessmentEmails 的 summary/nextStep 同样未转义） | 统一套用 sendReviewEmail 的转义模式 |
| S2 | [Users.ts:12](cms/src/collections/Users.ts:12) | `read: () => true`——任何人可 `/api/users` 拉取管理员邮箱/姓名（钓鱼/撞库素材），且 create/update/delete 未显式声明 | `read: ({ req }) => !!req.user` + 补齐写权限规则 |
| S3 | [server.ts](cms/src/server.ts) | rate limiter 未设 `trust proxy`，部署在代理后时 X-Forwarded-For 可伪造绕过 10 POST/min；in-memory 计数器多实例下失效 | `app.set('trust proxy', 1)`；上线多实例前换共享存储 |

注：Media 集合公开可读对营销站是**正常设计**（前端要取图），agent 建议收紧的意见不采纳。Reviews 公开免审核是**既定产品决策**，不列为缺陷——但建议加 honeypot 隐藏字段抵御机器人（不改变免审核模式）。

### 🟠 P1 — 工程质量

**前端**
- 图片体系：上述 4 张大 PNG 转 WebP + `next/image`/srcset（移动端 LCP 8.3s → 预计 <2.5s 的主要抓手）
- 字体：删 Cormorant Garamond；Montserrat + JetBrains Mono 改走 `next/font`（消除渲染阻塞，三页各省 0.6~1.7s）
- /quote：footer CLS 修复（错误提示预留高度 / `contain: layout`）+ 表单 `id`/`htmlFor` 显式关联 + slider 加 `<output>`
- **ESLint 配置缺失**（`frontend/` 无任何 .eslintrc，`npm run lint` 从未生效——CLAUDE.md 写的自检命令是空转的）
- 结构化数据补两块：/products 的 `Product` schema（3 个 package）、/reviews 的 `AggregateRating` + `Review` schema（SERP 富摘要直接相关）
- `as any` 逃逸 7 处（[news/page.tsx:28](frontend/src/app/news/page.tsx:28)、api/client.ts 错误处理、contact fallback 等）
- 首页缓存 13 天陈旧问题：复核 Vercel ISR 实际行为
- hero 视频（12MB）：加 `poster` 帧，评估 `preload="metadata"`

**CMS**
- 服务器端校验缺失：email/phone/postcode 只有前端校验，API 直打可绕过；textarea 无 maxLength（前端已有 AU 校验规则，照搬到 Payload `validate` 即可）
- SMTP 失败静默：邮件挂了 lead 照存但无人知晓——失败时给 lead 打 `notified: false` 标记 + admin 提醒
- **生产部署两个前置条件**（当前本地跑无碍，上线前必须解决）：
  - db-postgres 无 migrations 目录/流程，schema 变更靠 dev push，生产会出事
  - uploads 落本地磁盘，换到任何 PaaS 重新部署即丢文件 → S3/R2（@payloadcms/plugin-cloud-storage）
- CORS 里 localhost 源未按 NODE_ENV 区分
